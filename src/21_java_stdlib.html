Stream API

Stream là pipeline xử lý dữ liệu khai báo: nguồn → các bước trung gian (lười, chưa chạy) → một bước kết thúc (kích hoạt toàn bộ pipeline). Stream chỉ dùng được một lần.

record Order(String shop, String country, BigDecimal total, boolean flagged) {}

// lọc, biến đổi, thu thập
List riskyShops = orders.stream()
    .filter(Order::flagged)
    .map(Order::shop)
    .distinct()
    .sorted()
    .toList();                                           // Java 16, trả list bất biến

// nhóm và tổng hợp
Map countByCountry = orders.stream()
    .collect(Collectors.groupingBy(Order::country, Collectors.counting()));

Map revenueByShop = orders.stream()
    .collect(Collectors.groupingBy(Order::shop,
        Collectors.reducing(BigDecimal.ZERO, Order::total, BigDecimal::add)));

Map> split = orders.stream()
    .collect(Collectors.partitioningBy(Order::flagged));

Map latestByShop = orders.stream()
    .collect(Collectors.toMap(Order::shop, o -> o, (a, b) -> b));   // hàm merge khi trùng key

String csv = orders.stream().map(Order::shop).collect(Collectors.joining(",", "[", "]"));

// flatMap: làm phẳng
List allTags = customers.stream().flatMap(c -> c.tags().stream()).toList();

// số liệu
IntSummaryStatistics stats = orders.stream().mapToInt(o -> o.total().intValue()).summaryStatistics();
Optional biggest = orders.stream().max(Comparator.comparing(Order::total));
boolean anyFraud = orders.stream().anyMatch(Order::flagged);

Stream Gatherers Java 24

Gatherer là bước trung gian tự định nghĩa, lấp chỗ trống mà map/filter không làm được (cửa sổ, tích lũy có trạng thái).

Stream.of(1, 2, 3, 4, 5, 6, 7, 8).gather(Gatherers.windowFixed(3)).toList();
// [[1, 2, 3], [4, 5, 6], [7, 8]]

Stream.of(1, 2, 3, 4).gather(Gatherers.windowSliding(2)).toList();
// [[1, 2], [2, 3], [3, 4]]

Stream.of(1, 2, 3, 4).gather(Gatherers.scan(() -> 0, Integer::sum)).toList();
// [1, 3, 6, 10]  (tổng cộng dồn)

// gọi I/O song song bằng virtual threads, giữ nguyên thứ tự, tối đa 16 cùng lúc

parallelStream

parallelStream() chạy trên common ForkJoinPool dùng chung toàn JVM. Chỉ có lợi với dữ liệu lớn, tính toán CPU thuần, không có I/O và không có side effect. Với I/O, dùng virtual threads hoặc mapConcurrent.

Thread và ExecutorService

Không tạo Thread thủ công cho từng việc. ExecutorService quản lý thread, nhận task (Runnable / Callable) và trả Future.

// pool cố định cho việc nặng CPU: số thread ≈ số core
ExecutorService cpu = Executors.newFixedThreadPool(Runtime.getRuntime().availableProcessors());

Future f = cpu.submit(() -> heavyScore(order));        // Callable
Integer score = f.get(2, TimeUnit.SECONDS);                      // chờ có timeout

List> tasks = orders.stream().>map(o -> () -> heavyScore(o)).toList();
List> results = cpu.invokeAll(tasks);

// tắt đúng cách
cpu.shutdown();                                                  // không nhận task mới
if (!cpu.awaitTermination(30, TimeUnit.SECONDS)) cpu.shutdownNow();

// lập lịch
ScheduledExecutorService sched = Executors.newSingleThreadScheduledExecutor();
sched.scheduleAtFixedRate(this::flushMetrics, 0, 10, TimeUnit.SECONDS);

Từ Java 19, ExecutorService implement AutoCloseable: dùng trong try (var ex = ...) thì close() chờ mọi task xong.

Virtual threads Java 21

Virtual thread là thread nhẹ do JVM quản lý. Khi gặp I/O blocking, JVM "tháo" nó khỏi thread hệ điều hành (carrier) để chạy việc khác. Hệ quả: viết code blocking đơn giản như cũ nhưng chạy được hàng trăm nghìn tác vụ I/O đồng thời, không cần reactive/callback.

// mỗi task một virtual thread
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    List> futures = ips.stream()
        .map(ip -> executor.submit(() -> geo.lookup(ip)))     // code blocking bình thường
        .toList();
    for (var f : futures) IO.println(f.get());
}                                                             // close() chờ tất cả xong

Thread t = Thread.ofVirtual().name("worker-", 0).start(() -> process(msg));
Thread.startVirtualThread(() -> process(msg));
t.isVirtual();                                                // true

Pinning

Ở JDK 21–23, virtual thread bị "ghim" vào carrier khi blocking bên trong synchronized, làm mất lợi ích; lời khuyên khi đó là đổi sang ReentrantLock. Từ JDK 24 vấn đề này đã được sửa; chỉ còn ghim khi gọi native method hoặc foreign function. Theo dõi bằng sự kiện JFR jdk.VirtualThreadPinned.

// giới hạn 20 request đồng thời tới API ngoài dù có 10.000 virtual thread
private final Semaphore permits = new Semaphore(20);

IpInfo lookup(String ip) throws InterruptedException {
    permits.acquire();
    try { return client.get(ip); } finally { permits.release(); }
}

CompletableFuture

Ghép các bước bất đồng bộ thành chuỗi, tương tự Promise trong JavaScript.

ExecutorService io = Executors.newVirtualThreadPerTaskExecutor();

CompletableFuture shopF = CompletableFuture.supplyAsync(() -> shops.find(id), io);
CompletableFuture> rulesF = CompletableFuture.supplyAsync(() -> rules.byShop(id), io);

CompletableFuture dash = shopF
    .thenCombine(rulesF, Dashboard::new)                // ghép hai kết quả (≈ Promise.all cho 2)
    .orTimeout(3, TimeUnit.SECONDS)                     // quá hạn → TimeoutException
    .exceptionally(ex -> Dashboard.empty());            // ≈ .catch()

CompletableFuture risk = shopF
    .thenApply(Shop::country)                            // ≈ .then(x => ...)
    .thenCompose(c -> CompletableFuture.supplyAsync(() -> scorer.score(c), io));  // flatMap

CompletableFuture.allOf(shopF, rulesF).join();          // chờ tất cả; join() ném unchecked

Không truyền executor thì supplyAsync chạy trên ForkJoinPool.commonPool(), không hợp với I/O blocking. Với virtual threads, nhiều trường hợp có thể viết code tuần tự thay cho chuỗi CompletableFuture.

Đồng bộ hóa và Java Memory Model

Khi nhiều thread cùng đọc/ghi một biến, cần hai bảo đảm: nguyên tử (không bị chen ngang giữa chừng) và khả kiến (thread khác thấy giá trị mới). Java Memory Model định nghĩa quan hệ happens-before: unlock trước lock, ghi volatile trước đọc volatile, Thread.start() trước mọi hành động trong thread đó.

// 1. synchronized: nguyên tử + khả kiến
private int count;
public synchronized void inc() { count++; }

// 2. volatile: chỉ khả kiến, KHÔNG nguyên tử (count++ vẫn sai)
private volatile boolean running = true;
public void stop() { running = false; }

// 3. atomic: nguyên tử không cần khóa
private final AtomicLong requests = new AtomicLong();
requests.incrementAndGet();
private final LongAdder hits = new LongAdder();          // nhanh hơn khi ghi rất nhiều
hits.increment();

// 4. ConcurrentHashMap: thao tác gộp nguyên tử
ConcurrentHashMap perIp = new ConcurrentHashMap<>();
perIp.computeIfAbsent(ip, k -> new LongAdder()).increment();
perIp.merge(shop, 1L, Long::sum);

// 5. lock tường minh: có tryLock, timeout, nhiều condition
private final ReentrantLock lock = new ReentrantLock();
if (lock.tryLock(100, TimeUnit.MILLISECONDS)) {
    try { refreshToken(); } finally { lock.unlock(); }
}
ReadWriteLock rw = new ReentrantReadWriteLock();         // nhiều reader, một writer

// 6. điều phối
CountDownLatch ready = new CountDownLatch(3);            // chờ 3 sự kiện
ready.countDown(); ready.await();
Nguyên tắc

Cách an toàn nhất là không chia sẻ trạng thái có thể sửa: dùng object bất biến (record), truyền dữ liệu qua BlockingQueue, hoặc giới hạn trạng thái trong một thread. Ưu tiên tiện ích của java.util.concurrent hơn wait()/notify().

ScopedValue Java 25

Thay thế ThreadLocal để truyền dữ liệu ngữ cảnh (tenant, user, request-id) xuống call stack mà không cần tham số. Giá trị bất biến, chỉ tồn tại trong phạm vi run, rẻ với virtual threads. Tương đương AsyncLocalStorage trong Node.

public final class RequestContext {

// ở tầng nhận request
ScopedValue.where(RequestContext.SHOP, "demo.myshopify.com")

Structured Concurrency preview

Coi một nhóm tác vụ con như một đơn vị: nếu một tác vụ lỗi thì các tác vụ còn lại bị hủy, và không tác vụ nào "rò" ra ngoài block. Tới JDK 27 vẫn là preview (cần --enable-preview), API có thể còn đổi.

record Profile(User user, List orders) {}

Profile load(long id) throws InterruptedException {
    try (var scope = StructuredTaskScope.open()) {        // mặc định: tất cả phải thành công
        Subtask user = scope.fork(() -> userRepo.find(id));
        Subtask> orders = scope.fork(() -> orderRepo.byUser(id));
        scope.join();                                     // một subtask lỗi → hủy phần còn lại và ném lỗi
        return new Profile(user.get(), orders.get());
    }
}

// lấy kết quả của tác vụ nhanh nhất, hủy phần còn lại
try (var scope = StructuredTaskScope.open(Joiner.anySuccessfulOrThrow())) {
    scope.fork(() -> mirrorA.fetch());
    scope.fork(() -> mirrorB.fetch());
    return scope.join();
}
