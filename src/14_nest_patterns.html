Tổng quan các pattern

Docs chính thức dạy từng viên gạch; phần này ghép chúng lại thành các pattern hay gặp trong dự án NestJS thực tế, tổng hợp từ docs, các repo tham khảo phổ biến (Domain-Driven Hexagon, nestjs-cls) và kinh nghiệm cộng đồng. Không phải dự án nào cũng cần hết: chọn pattern theo vấn đề bạn đang gặp.

Vấn đềPattern
Code bắt đầu rối, không biết đặt logic ở đâuLayered module, Repository
Muốn đổi DB/SDK/nhà cung cấp mà không sửa business logicPorts & Adapters
Response và lỗi mỗi chỗ một kiểuEnvelope + pagination, Domain errors

Layered feature module

Mỗi tính năng là một module, bên trong chia ba tầng với trách nhiệm rõ ràng. Đây là điểm xuất phát mặc định cho hầu hết dự án Nest.

src/
├── common/                 # filter, interceptor, pipe, decorator dùng chung
├── config/                 # registerAs namespaces + validate env
├── orders/
│   ├── orders.module.ts
│   ├── orders.controller.ts   # HTTP: nhận DTO, gọi service, không chứa logic
│   ├── orders.service.ts      # business logic, không biết HTTP
│   ├── orders.repository.ts   # truy cập DB, không chứa logic nghiệp vụ
│   ├── dto/                   # input (class-validator) và output
│   └── schemas/               # Mongoose schema / entity
└── app.module.ts
Controller

Parse input, gọi đúng một method service, trả kết quả. Không gọi trực tiếp model DB.

Service

Quy tắc nghiệp vụ, điều phối repository và client ngoài. Ném exception nghiệp vụ.

Repository

Query, index, projection, transaction. Trả object thuần (lean()).

Đừng làm quá

Thêm tầng thì thêm chi phí đọc code. Nếu service chỉ chuyển tiếp nguyên xi sang repository cho một query đơn giản, chấp nhận gộp. Tầng chỉ đáng giá khi nó tách được một lý do thay đổi riêng.

Repository với abstract class làm token

TypeScript interface không tồn tại lúc runtime nên không làm token DI được. Abstract class vừa là "hợp đồng" vừa là token, không cần @Inject().

// hợp đồng
export abstract class RulesRepository {
  abstract findActive(shop: string): Promise;
  abstract create(shop: string, data: NewRule): Promise;
}

// cài đặt Mongo
@Injectable()
export class MongoRulesRepository extends RulesRepository {
  constructor(@InjectModel(RuleDoc.name) private readonly model: Model) { super(); }

  findActive(shop: string) {
    return this.model.find({ shop, enabled: true }).sort({ priority: -1 }).lean();
  }
  async create(shop: string, data: NewRule) {
    return (await this.model.create({ shop, ...data })).toObject();
  }
}

// binding
@Module({
  providers: [RulesService, { provide: RulesRepository, useClass: MongoRulesRepository }],
})
export class RulesModule {}

// service chỉ biết hợp đồng
@Injectable()
export class RulesService {
  constructor(private readonly repo: RulesRepository) {}
}

// test: thay bằng bản in-memory, không cần mock Mongoose
{ provide: RulesRepository, useClass: InMemoryRulesRepository }

Ports & Adapters (Hexagonal)

Mở rộng ý tưởng repository cho mọi phụ thuộc bên ngoài: DB, API IP lookup, gửi mail, message broker. Lõi nghiệp vụ chỉ phụ thuộc vào port (abstract class); adapter ở tầng infrastructure cài đặt port. Phụ thuộc luôn hướng vào trong.

src/risk/
├── domain/             # entity, value object, domain error — không import @nestjs, mongoose
├── application/
│   ├── ports/          # IpLookupPort, RiskEventsPort (abstract class)
│   └── score-order.use-case.ts
├── infrastructure/
│   ├── ipinfo.adapter.ts       # implements IpLookupPort bằng HTTP
│   └── rabbit-events.adapter.ts
├── interface/
│   └── risk.controller.ts
└── risk.module.ts      # nơi duy nhất nối port với adapter

export abstract class IpLookupPort {
  abstract lookup(ip: string): Promise<{ country: string; isProxy: boolean }>;
}

@Injectable()
export class ScoreOrderUseCase {
  constructor(private readonly ip: IpLookupPort, private readonly events: RiskEventsPort) {}

  async execute(order: OrderInput) {
    const info = await this.ip.lookup(order.ip);
    const score = info.isProxy ? 80 : 10;            // logic thuần, test không cần mạng
    await this.events.scored(order.id, score);
    return score;
  }
}

@Module({
  providers: [
    ScoreOrderUseCase,
    { provide: IpLookupPort, useClass: IpInfoAdapter },
    { provide: RiskEventsPort, useClass: RabbitRiskEventsAdapter },
  ],
})
export class RiskModule {}
Khi nào đáng dùng

Domain phức tạp, tuổi thọ dài, có khả năng đổi nhà cung cấp. Với service CRUD nhỏ, hexagonal tạo nhiều file mà ít giá trị.

Response envelope và pagination

Thống nhất hình dạng response cho client: interceptor bọc kết quả thành công, filter bọc lỗi (xem Exception filters), DTO phân trang dùng lại ở mọi danh sách.

export class PageQuery {
  @Type(() => Number) @IsInt() @Min(1) page = 1;
  @Type(() => Number) @IsInt() @Min(1) @Max(100) limit = 20;
  get skip() { return (this.page - 1) * this.limit; }
}

export class Paginated {
  constructor(public items: T[], public total: number, public page: number, public limit: number) {}
}

// repository
async list(shop: string, q: PageQuery) {
  const [items, total] = await Promise.all([
    this.model.find({ shop }).skip(q.skip).limit(q.limit).lean(),
    this.model.countDocuments({ shop }),
  ]);
  return new Paginated(items, total, q.page, q.limit);
}

// interceptor: tách meta phân trang ra khỏi data
@Injectable()
export class EnvelopeInterceptor implements NestInterceptor {
  intercept(_: ExecutionContext, next: CallHandler) {
    return next.handle().pipe(map((res) =>
      res instanceof Paginated
        ? { success: true, data: res.items, meta: { total: res.total, page: res.page, limit: res.limit } }
        : { success: true, data: res },
    ));
  }
}

Domain errors tách khỏi HTTP

Service ném lỗi nghiệp vụ không biết gì về HTTP; một filter duy nhất ánh xạ sang status code. Nhờ vậy cùng service dùng được trong HTTP controller, RabbitMQ consumer và cron mà không phải ném NotFoundException trong worker.

export abstract class DomainError extends Error {
  abstract readonly code: string;
  constructor(message: string, readonly details?: Record) { super(message); }
}
export class QuotaExceededError extends DomainError { readonly code = 'QUOTA_EXCEEDED'; }
export class RuleNotFoundError extends DomainError { readonly code = 'RULE_NOT_FOUND'; }

const STATUS: Record = { QUOTA_EXCEEDED: 429, RULE_NOT_FOUND: 404 };

@Catch(DomainError)
export class DomainErrorFilter implements ExceptionFilter {
  constructor(private readonly adapterHost: HttpAdapterHost) {}

  catch(e: DomainError, host: ArgumentsHost) {
    if (host.getType() !== 'http') throw e;                   // RPC/WS tự xử lý
    const status = STATUS[e.code] ?? 400;
    this.adapterHost.httpAdapter.reply(host.switchToHttp().getResponse(),
      { success: false, error: { code: e.code, message: e.message, details: e.details } }, status);
  }
}

Strategy registry

Thay chuỗi switch bằng một bản đồ "loại → implementation" do DI dựng sẵn. Thêm loại mới chỉ cần thêm class, không sửa code cũ.

export abstract class Notifier {
  abstract readonly channel: 'email' | 'slack' | 'sms';
  abstract send(to: string, msg: string): Promise;
}

export const NOTIFIERS = Symbol('NOTIFIERS');

@Module({
  providers: [
    EmailNotifier, SlackNotifier, SmsNotifier,
    {
      provide: NOTIFIERS,
      inject: [EmailNotifier, SlackNotifier, SmsNotifier],
      useFactory: (...list: Notifier[]) => new Map(list.map((n) => [n.channel, n])),
    },
    NotifyService,
  ],
})
export class NotifyModule {}

@Injectable()
export class NotifyService {
  constructor(@Inject(NOTIFIERS) private readonly notifiers: Map) {}

  send(channel: string, to: string, msg: string) {
    const n = this.notifiers.get(channel);
    if (!n) throw new BadRequestException(`Kênh ${channel} không hỗ trợ`);
    return n.send(to, msg);
  }
}

Khi danh sách strategy lớn hoặc nằm ở nhiều module, dùng decorator + DiscoveryService để registry tự tìm, khỏi khai báo inject thủ công.

Request context với AsyncLocalStorage nestjs-cls

Thay vì REQUEST scope (làm cả chuỗi provider bị tạo lại mỗi request), lưu dữ liệu theo request trong AsyncLocalStorage. Mọi provider vẫn là singleton nhưng đọc được shopId, requestId, user của request hiện tại ở bất kỳ đâu, kể cả trong logger.

npm i nestjs-cls
export interface AppStore extends ClsStore { shop?: string; userId?: string }

@Module({
  imports: [
    ClsModule.forRoot({
      global: true,
      middleware: {
        mount: true,
        generateId: true,
        idGenerator: (req: Request) => (req.headers['x-request-id'] as string) ?? randomUUID(),
        setup: (cls, req: Request) => cls.set('shop', req.headers['x-shop-domain'] as string),
      },
    }),
  ],
})
export class AppModule {}

@Injectable()
export class AuditService {
  constructor(private readonly cls: ClsService) {}

  record(action: string) {
    return this.repo.insert({
      action,
      shop: this.cls.get('shop'),
      requestId: this.cls.getId(),
    });
  }
}

// ngoài HTTP (consumer, cron): tự mở context
await this.cls.run(async () => {
  this.cls.set('shop', msg.shop);
  await this.handler.process(msg);
});

Không muốn thêm thư viện: tự tạo new AsyncLocalStorage<Store>() từ node:async_hooks và gọi als.run(store, () => next()) trong một middleware.

Unit of Work / Transactional

Khi một use case ghi nhiều collection, cần transaction. Truyền session qua từng tham số rất dễ quên; plugin @nestjs-cls/transactional cộng đồng lưu transaction trong CLS và cho phép đánh dấu bằng decorator.

npm i @nestjs-cls/transactional @nestjs-cls/transactional-adapter-mongoose
ClsModule.forRoot({
  global: true,
  plugins: [
    new ClsPluginTransactional({
      adapter: new TransactionalAdapterMongoose({ mongooseConnectionToken: getConnectionToken() }),
    }),
  ],
});

@Injectable()
export class OrdersRepository {
  constructor(
    @InjectModel(Order.name) private readonly model: Model,
    private readonly txHost: TransactionHost,
  ) {}

  create(data: NewOrder) {
    return this.model.create([data], { session: this.txHost.tx });  // tx = ClientSession hiện tại
  }
}

@Injectable()
export class CheckoutService {
  @Transactional()                       // mọi repository bên trong dùng chung một transaction
  async placeOrder(dto: PlaceOrderDto) {
    const [order] = await this.orders.create(dto);
    await this.quota.decrement(dto.shop);
    await this.outbox.add('order.created', { id: order.id });   // xem pattern Outbox
    return order;
  }
}
MongoDB

Transaction cần replica set (kể cả khi dev local). Với TypeORM/Prisma có adapter tương ứng; tự viết thì dùng dataSource.transaction() hoặc prisma.$transaction() và truyền tx xuống.

Transactional outbox

Vấn đề "dual write": ghi DB thành công rồi publish lên RabbitMQ thất bại (hoặc ngược lại) làm hai hệ thống lệch nhau. Outbox giải quyết bằng cách ghi message vào một collection outbox trong cùng transaction với dữ liệu nghiệp vụ; một tiến trình relay đọc outbox và publish, đánh dấu đã gửi. Kết quả là "at-least-once": consumer phải idempotent.

@Schema({ collection: 'outbox', timestamps: true })
export class OutboxMessage {
  @Prop({ required: true }) type: string;
  @Prop({ type: Object, required: true }) payload: Record;
  @Prop({ default: 'pending', index: true }) status: 'pending' | 'sent';
  @Prop({ default: 0 }) attempts: number;
}

@Injectable()
export class OutboxService {
  constructor(
    @InjectModel(OutboxMessage.name) private readonly model: Model,
    private readonly txHost: TransactionHost,
  ) {}

  add(type: string, payload: Record) {
    return this.model.create([{ type, payload }], { session: this.txHost.tx });
  }
}

@Injectable()
export class OutboxRelay {
  constructor(
    @InjectModel(OutboxMessage.name) private readonly model: Model,
    private readonly amqp: AmqpConnection,
  ) {}

  @Interval(1_000)
  async flush() {
    const batch = await this.model.find({ status: 'pending' }).sort({ _id: 1 }).limit(100).lean();
    for (const m of batch) {
      await this.amqp.publish('events', m.type, { id: String(m._id), ...m.payload }, { persistent: true });
      await this.model.updateOne({ _id: m._id }, { $set: { status: 'sent' } });
    }
  }
}

Chạy relay ở nhiều instance thì bọc flush() trong distributed lock, hoặc "claim" từng message bằng findOneAndUpdate({'{'} status: 'pending' {'}'}, {'{'} $set: {'{'} status: 'processing' {'}'} {'}'}). Có thể thay polling bằng MongoDB change streams.

Idempotency

Phía HTTP: Idempotency-Key

Client gửi header Idempotency-Key; server lưu kết quả lần đầu và trả lại đúng kết quả đó cho các lần retry.

@Injectable()
export class IdempotencyInterceptor implements NestInterceptor {
  constructor(@Inject(REDIS) private readonly redis: Redis) {}

  async intercept(ctx: ExecutionContext, next: CallHandler) {
    const req = ctx.switchToHttp().getRequest();
    const key = req.headers['idempotency-key'];
    if (!key) return next.handle();

    const redisKey = `idem:${req.user?.sub ?? 'anon'}:${key}`;
    const acquired = await this.redis.set(redisKey, 'PENDING', 'EX', 86_400, 'NX');
    if (!acquired) {
      const saved = await this.redis.get(redisKey);
      if (saved === 'PENDING') throw new ConflictException('Request với key này đang được xử lý');
      return of(JSON.parse(saved!));                      // trả lại kết quả cũ
    }

    return next.handle().pipe(
      mergeMap(async (res) => {
        await this.redis.set(redisKey, JSON.stringify(res), 'EX', 86_400);
        return res;
      }),
      catchError((err) => from(this.redis.del(redisKey)).pipe(mergeMap(() => throwError(() => err)))),
    );
  }
}

Phía consumer: inbox

Message broker có thể giao trùng. Ghi lại id message đã xử lý với unique index; gặp lỗi trùng khóa thì bỏ qua.

async handle(msg: { id: string; shop: string }) {
  try {
    await this.processed.create({ _id: msg.id, at: new Date() });   // unique theo _id
  } catch (e: any) {
    if (e.code === 11000) return;                                  // đã xử lý rồi
    throw e;
  }
  await this.doWork(msg);
}

Cách đơn giản hơn khi được: thiết kế thao tác tự nhiên là idempotent, như upsert theo khóa tự nhiên (shop + orderId) thay vì insert, hoặc $set thay vì $inc.

Distributed lock

Đảm bảo một cron/relay chỉ chạy trên một instance tại một thời điểm. Khóa Redis với token ngẫu nhiên, chỉ chủ khóa mới được xóa.

const RELEASE = `if redis.call('get', KEYS[1]) == ARGV[1] then return redis.call('del', KEYS[1]) else return 0 end`;

@Injectable()
export class LockService {
  constructor(@Inject(REDIS) private readonly redis: Redis) {}

  async run(name: string, ttlMs: number, fn: () => Promise): Promise {
    const key = `lock:${name}`;
    const token = randomUUID();
    const ok = await this.redis.set(key, token, 'PX', ttlMs, 'NX');
    if (!ok) return null;                        // instance khác đang chạy
    try {
      return await fn();
    } finally {
      await this.redis.eval(RELEASE, 1, key, token);
    }
  }
}

@Cron(CronExpression.EVERY_MINUTE)
syncUsage() {
  return this.lock.run('sync-usage', 55_000, () => this.usage.sync());
}

TTL phải dài hơn thời gian chạy dự kiến; job dài thì gia hạn khóa định kỳ. Docs v12 giới thiệu @nestjs/locks với @OnOneInstance() cho đúng việc này.

Modular monolith

Một codebase, một lần deploy, nhưng module có ranh giới như microservice. Khi cần tách service sau này, ranh giới đã sẵn.

  • Mỗi module chỉ exports một "facade" service. Không export repository, model hay schema.
  • Module A không import file nội bộ của module B (../billing/billing.repository). Có thể ép bằng eslint-plugin-boundaries hoặc dependency-cruiser.
  • Ghi chéo giữa module đi qua facade; phản ứng phụ (gửi mail, cập nhật thống kê) đi qua event.
  • Mỗi module sở hữu collection của mình; module khác không query thẳng.
  • Dùng CQRS chỉ khi luồng đọc và ghi khác nhau rõ rệt.
@Module({
  imports: [MongooseModule.forFeature([{ name: Plan.name, schema: PlanSchema }])],
  providers: [BillingService, PlanRepository, ShopifyBillingClient],
  exports: [BillingService],      // chỉ facade được lộ ra ngoài
})
export class BillingModule {}

Graceful shutdown

Khi Kubernetes gửi SIGTERM, ứng dụng nên ngừng nhận việc mới, làm xong việc đang dở, rồi mới đóng kết nối.

// main.ts
const app = await NestFactory.create(AppModule, { forceCloseConnections: true });
app.enableShutdownHooks();

@Injectable()
export class ShutdownState implements BeforeApplicationShutdown {
  shuttingDown = false;
  beforeApplicationShutdown() { this.shuttingDown = true; }   // health readiness trả 503
}

@Injectable()
export class OrdersConsumer implements OnModuleDestroy {
  private inFlight = new Set>();

  async onModuleDestroy() {
    await this.channel.cancel(this.tag);           // 1. ngừng nhận message mới
    await Promise.allSettled([...this.inFlight]);   // 2. đợi message đang xử lý
  }
}
// 3. Mongo/Redis đóng ở onApplicationShutdown của module tương ứng

Thêm preStop sleep vài giây trong manifest Kubernetes để load balancer kịp gỡ pod trước khi app ngừng nhận request.

Checklist trước khi lên production

  • ValidationPipe global với whitelist: true.
  • Biến môi trường được validate lúc khởi động (fail fast).
  • Exception filter global, log lỗi 5xx có stack và request-id.
  • Log dạng JSON, không log token, mật khẩu, PII.
  • Security headers (helmet), CORS whitelist cụ thể, rate limit cho endpoint đăng nhập.
  • app.enableShutdownHooks() và consumer dừng nhận message trong onModuleDestroy.
  • Health check /health (liveness) và kiểm tra DB/Redis (readiness).
  • Index cho mọi query nóng; không synchronize: true với SQL.
  • Cron/relay có khóa phân tán khi chạy nhiều replica.
  • Consumer idempotent, message lỗi đi vào dead-letter queue.
  • Swagger chỉ bật ở môi trường không phải production, hoặc có bảo vệ.
  • Build bằng SWC/tsc, chạy node dist/main, không chạy nest start trong container.
