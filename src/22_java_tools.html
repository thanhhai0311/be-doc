Đóng gói

  • jar: gói class thành file .jar; "fat jar" chứa cả dependency (Maven Shade, Spring Boot plugin).
  • jlink: tạo runtime chỉ gồm module cần thiết, image Docker nhỏ hơn nhiều.
  • jpackage: đóng gói thành bộ cài native (.deb, .msi, .dmg).

Testing: JUnit, AssertJ, Mockito

import org.junit.jupiter.api.*;
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.CsvSource;
import static org.assertj.core.api.Assertions.*;
import static org.mockito.Mockito.*;

@ExtendWith(MockitoExtension.class)
class RiskServiceTest {

    @Mock IpLookup ipLookup;                     // mock phụ thuộc
    @InjectMocks RiskService service;            // inject mock vào constructor

    @Test
    @DisplayName("IP proxy bị chấm điểm cao")
    void proxyIsRisky() {
        when(ipLookup.lookup("1.2.3.4")).thenReturn(new IpInfo("VN", true));

        int score = service.score("1.2.3.4");

        assertThat(score).isGreaterThanOrEqualTo(80);
        verify(ipLookup, times(1)).lookup("1.2.3.4");
    }

    @Test
    void invalidIpThrows() {
        assertThatThrownBy(() -> service.score("abc"))
            .isInstanceOf(IllegalArgumentException.class)
            .hasMessageContaining("IP");
    }

    @ParameterizedTest
    @CsvSource({ "VN,false,10", "US,true,80" })
    void scoreTable(String country, boolean proxy, int expected) {
        when(ipLookup.lookup(any())).thenReturn(new IpInfo(country, proxy));
        assertThat(service.score("8.8.8.8")).isEqualTo(expected);
    }
}

Vòng đời: @BeforeEach, @AfterEach, @BeforeAll/@AfterAll (static). Test tích hợp với DB/Redis/RabbitMQ thật dùng Testcontainers lib để khởi động container trong test.

GC, tuning và chẩn đoán

CollectorFlagHợp với
G1 (mặc định)-XX:+UseG1GCĐa số ứng dụng server, cân bằng throughput và độ trễ. Từ JDK 27 là mặc định cả trên máy nhỏ.
ZGC (generational)-XX:+UseZGCHeap lớn, cần pause dưới mili-giây.
Shenandoah-XX:+UseShenandoahGCĐộ trễ thấp (có trong nhiều bản OpenJDK, không có trong Oracle JDK).
Parallel-XX:+UseParallelGCBatch job cần throughput tối đa, chấp nhận pause dài.
Serial-XX:+UseSerialGCHeap rất nhỏ, một core.
# chạy trong container: để JVM tính heap theo giới hạn RAM của container
java -XX:MaxRAMPercentage=75 -XX:+UseG1GC -XX:MaxGCPauseMillis=200 \
     -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/tmp \
     -Xlog:gc*:file=/tmp/gc.log:time,uptime \
     -jar app.jar

# hoặc cố định heap
java -Xms2g -Xmx2g -jar app.jar

Công cụ chẩn đoán có sẵn trong JDK

jcmd                                  # liệt kê process Java
jcmd  Thread.print               # dump thread (tìm deadlock, thread bị treo)
jcmd  GC.heap_info               # tình trạng heap
jcmd  GC.heap_dump /tmp/heap.hprof
jcmd  VM.flags                   # flag JVM đang dùng

# Java Flight Recorder: profiling chi phí rất thấp, dùng được trên production
jcmd  JFR.start duration=60s filename=/tmp/rec.jfr
java -XX:StartFlightRecording=duration=60s,filename=rec.jfr,settings=profile -jar app.jar
jfr print --events jdk.VirtualThreadPinned rec.jfr

Mở file .jfr bằng JDK Mission Control; mở heap dump bằng Eclipse MAT để tìm rò rỉ bộ nhớ.

Logging

Chuẩn phổ biến: code gọi API SLF4J lib, cài đặt thực tế là Logback hoặc Log4j2. Thư viện chỉ phụ thuộc SLF4J; ứng dụng chọn backend.

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class OrderSync {
    private static final Logger log = LoggerFactory.getLogger(OrderSync.class);

    void sync(Order o) {
        log.info("Sync order {} for shop {}", o.id(), o.shop());   // placeholder: không nối chuỗi
        try {
            client.push(o);
        } catch (IOException e) {
            log.error("Sync failed for order {}", o.id(), e);       // exception để cuối cùng
        }
        if (log.isDebugEnabled()) log.debug("payload={}", toJson(o)); // tránh tính toán tốn kém
    }
}

Dùng MDC (MDC.put("requestId", id)) để gắn request-id vào mọi dòng log, và encoder JSON (logstash-logback-encoder) cho môi trường production.
