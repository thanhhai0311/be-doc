Custom providers

Viết providers: [CatsService] là cách viết tắt của {'{'} provide: CatsService, useClass: CatsService {'}'}. Dạng đầy đủ cho phép kiểm soát token và cách tạo instance. Có bốn kiểu:

KiểuDùng khi
useValueHằng số, object cấu hình, mock trong test.
useClassChọn class cài đặt lúc runtime (theo môi trường), hoặc bind interface → implementation.
useFactoryInstance cần tính toán, cần provider khác, hoặc cần await (kết nối DB, SDK).
useExistingTạo alias: hai token trỏ cùng một instance.
export const REDIS = Symbol('REDIS');
export const APP_NAME = 'APP_NAME';

@Module({
  providers: [
    // 1. useValue
    { provide: APP_NAME, useValue: 'fraud-api' },

    // 2. useClass: chọn implementation theo môi trường
    {
      provide: MailSender,                               // abstract class làm token
      useClass: process.env.NODE_ENV === 'test' ? FakeMailSender : SesMailSender,
    },

    // 3. useFactory: có inject, có async
    {
      provide: REDIS,
      inject: [ConfigService, { token: 'REDIS_OPTIONS', optional: true }],
      useFactory: async (config: ConfigService, extra?: RedisOptions) => {
        const client = new Redis(config.getOrThrow('REDIS_URL'), extra);
        await client.ping();                             // Nest đợi Promise xong mới tạo provider phụ thuộc
        return client;
      },
    },

    // 4. useExisting: alias
    { provide: 'LegacyLogger', useExisting: AppLogger },
  ],
  exports: [REDIS, MailSender],
})
export class InfraModule {}

// inject token không phải class phải dùng @Inject
constructor(@Inject(REDIS) private readonly redis: Redis) {}
Async provider

Factory trả về Promise thì Nest đợi resolve trước khi khởi tạo bất kỳ class nào phụ thuộc vào nó. Đây là cách chuẩn để "ứng dụng chỉ khởi động khi đã kết nối xong DB". Đặt biến môi trường NEST_DEBUG=true để xem log quá trình resolve DI.

Dynamic modules

Module tĩnh luôn giống nhau ở mọi nơi import. Dynamic module nhận tham số và trả về module được cấu hình riêng, ví dụ ConfigModule.forRoot({'{'} isGlobal: true {'}'}). Static method trả về object DynamicModule, trong đó module là bắt buộc, các khóa khác bổ sung vào metadata của @Module().

Quy ước đặt tên

MethodÝ nghĩaVí dụ
forRoot / forRootAsyncCấu hình một lần ở root, dùng chung toàn appMongooseModule.forRoot(uri)
register / registerAsyncMỗi nơi import có cấu hình riêngHttpModule.register({'{'} timeout {'}'})
forFeatureDùng lại kết nối của forRoot, thêm phần riêng cho moduleMongooseModule.forFeature([...])

Viết tay

export interface ShopifyOptions { apiKey: string; apiSecret: string; apiVersion: string }
export const SHOPIFY_OPTIONS = Symbol('SHOPIFY_OPTIONS');

@Module({})
export class ShopifyModule {
  static forRoot(options: ShopifyOptions): DynamicModule {
    return {
      module: ShopifyModule,
      global: true,
      providers: [{ provide: SHOPIFY_OPTIONS, useValue: options }, ShopifyClient],
      exports: [ShopifyClient],
    };
  }
}

Dùng ConfigurableModuleBuilder

Viết tay cả forRoot lẫn forRootAsync (hỗ trợ useFactory, useClass, useExisting, inject, imports) khá dài. ConfigurableModuleBuilder sinh sẵn toàn bộ.

import { ConfigurableModuleBuilder } from '@nestjs/common';

export const {
  ConfigurableModuleClass,
  MODULE_OPTIONS_TOKEN,
  OPTIONS_TYPE,
  ASYNC_OPTIONS_TYPE,
} = new ConfigurableModuleBuilder()
  .setClassMethodName('forRoot')               // sinh forRoot / forRootAsync (mặc định là register)
  .setFactoryMethodName('createShopifyOptions') // tên method khi dùng useClass
  .setExtras({ isGlobal: false }, (def, extras) => ({ ...def, global: extras.isGlobal }))
  .build();

@Module({ providers: [ShopifyClient], exports: [ShopifyClient] })
export class ShopifyModule extends ConfigurableModuleClass {}

@Injectable()
export class ShopifyClient {
  constructor(@Inject(MODULE_OPTIONS_TOKEN) private readonly opts: ShopifyOptions) {}
}

// app.module.ts
ShopifyModule.forRootAsync({
  isGlobal: true,
  imports: [ConfigModule],
  inject: [ConfigService],
  useFactory: (c: ConfigService) => ({
    apiKey: c.getOrThrow('SHOPIFY_API_KEY'),
    apiSecret: c.getOrThrow('SHOPIFY_API_SECRET'),
    apiVersion: '2025-10',
  }),
});

Injection scopes

ScopeVòng đời instanceDùng khi
Scope.DEFAULTMột instance cho cả app (singleton)Gần như mọi trường hợp. Nhanh nhất.
Scope.REQUESTTạo mới cho mỗi request, bị hủy sau requestCần dữ liệu riêng từng request (tenant, user) mà không truyền tham số.
Scope.TRANSIENTMỗi nơi inject nhận một instance riêngLogger có setContext() riêng cho từng class.
import { Inject, Injectable, Scope } from '@nestjs/common';
import { REQUEST } from '@nestjs/core';

@Injectable({ scope: Scope.REQUEST })
export class TenantContext {
  constructor(@Inject(REQUEST) private readonly req: Request) {}
  get shopId() { return this.req.headers['x-shop-id'] as string; }
}
Scope "lan truyền" lên trên

Nếu OrdersService inject TenantContext (REQUEST), thì OrdersService và controller dùng nó cũng thành REQUEST-scoped, tức là tạo mới mỗi request. Request scope cũng không chạy lifecycle hook (onModuleInit…). Với dữ liệu theo request, nên dùng AsyncLocalStorage / nestjs-cls (xem pattern Request context) để giữ mọi thứ là singleton.

Durable providers (dành cho multi-tenant): đánh dấu @Injectable({'{'} scope: Scope.REQUEST, durable: true {'}'}) và đăng ký một ContextIdStrategy qua ContextIdFactory.apply(). Nest khi đó tạo một cây DI cho mỗi tenant thay vì mỗi request. Docs lưu ý cách này chỉ hợp với số tenant nhỏ.

Circular dependency, ModuleRef và lazy loading

Phụ thuộc vòng

Khi A cần B và B cần A, TypeScript import ra undefined tại thời điểm decorator chạy. Giải pháp tạm là forwardRef ở cả hai phía:

// provider
@Injectable()
export class OrdersService {
  constructor(@Inject(forwardRef(() => CustomersService)) private customers: CustomersService) {}
}
@Injectable()
export class CustomersService {
  constructor(@Inject(forwardRef(() => OrdersService)) private orders: OrdersService) {}
}

// module
@Module({ imports: [forwardRef(() => CustomersModule)] })
export class OrdersModule {}
Nên làm

Vòng phụ thuộc thường là dấu hiệu thiết kế sai. Cách xử lý triệt để: tách phần dùng chung ra module thứ ba, hoặc đổi một chiều gọi thành event (A phát event, B lắng nghe). Tránh file barrel index.ts import qua lại trong cùng thư mục, đây là nguồn circular import phổ biến.

ModuleRef

ModuleRef cho phép lấy provider theo token lúc runtime, hữu ích khi token chỉ biết lúc chạy (strategy theo tên).

@Injectable()
export class ExportService {
  constructor(private readonly moduleRef: ModuleRef) {}

  async run(format: 'csv' | 'xlsx') {
    const exporter = this.moduleRef.get(format === 'csv' ? CsvExporter : XlsxExporter, { strict: false });
    // provider REQUEST/TRANSIENT phải dùng resolve() và nên truyền contextId
    const scoped = await this.moduleRef.resolve(ReportBuilder, ContextIdFactory.create());
    // tạo instance của class chưa đăng ký nhưng vẫn được inject
    const tmp = await this.moduleRef.create(TempWorker);
  }
}

Lazy-loading module

Mặc định mọi module nạp lúc khởi động. Với serverless hoặc worker cần cold start nhanh, nạp module khi cần bằng LazyModuleLoader:

@Injectable()
export class ReportsService {
  constructor(private readonly lazy: LazyModuleLoader) {}

  async generate() {
    const { PdfModule } = await import('./pdf/pdf.module');
    const ref = await this.lazy.load(() => PdfModule);   // cache sau lần đầu
    return ref.get(PdfService).render();
  }
}

Hạn chế: module lazy không chứa được controller/gateway/resolver, không chạy lifecycle hook và không global được.

Execution context và Reflector

Guard, interceptor, filter phải chạy được cho HTTP, microservice, WebSocket và GraphQL. Nest đưa cho chúng một lớp trừu tượng:

  • ArgumentsHost: getType() trả về 'http' | 'rpc' | 'ws' (hoặc 'graphql'); switchToHttp(), switchToRpc(), switchToWs() lấy đối tượng đúng loại.
  • ExecutionContext kế thừa ArgumentsHost, thêm getClass() (controller) và getHandler() (method) để đọc metadata.
canActivate(ctx: ExecutionContext) {
  switch (ctx.getType<'http' | 'rpc' | 'ws' | 'graphql'>()) {
    case 'http':    return this.checkHttp(ctx.switchToHttp().getRequest());
    case 'rpc':     return this.checkRpc(ctx.switchToRpc().getData());
    case 'ws':      return this.checkWs(ctx.switchToWs().getClient());
    case 'graphql': return this.checkHttp(GqlExecutionContext.create(ctx).getContext().req);
  }
}

Đọc metadata với Reflector

MethodHành vi
get(key, target)Đọc metadata trên một target (handler hoặc class).
getAllAndOverride(key, [handler, class])Lấy giá trị đầu tiên khác undefined: method ghi đè class.
getAllAndMerge(key, [handler, class])Gộp mảng/object từ cả method và class.
@Roles(['staff'])
@Controller('orders')
export class OrdersController {
  @Roles(['admin'])
  @Delete(':id')
  remove() {}
}
// getAllAndOverride(Roles, ...) → ['admin']
// getAllAndMerge(Roles, ...)    → ['admin', 'staff']

Lifecycle events

Provider, controller và module có thể implement các hook sau:

  1. onModuleInit()Ngay sau khi phụ thuộc của module đã resolve. Hợp để kết nối, warm cache.
  2. onApplicationBootstrap()Khi mọi module đã init, trước khi bắt đầu nhận kết nối.
  3. app.listen()Ứng dụng phục vụ request.
  4. onModuleDestroy()Khi nhận tín hiệu tắt (SIGTERM) hoặc gọi app.close().
  5. beforeApplicationShutdown(signal)Sau khi mọi onModuleDestroy hoàn tất, trước khi đóng kết nối HTTP.
  6. onApplicationShutdown(signal)Sau khi kết nối đã đóng, bước cuối cùng.
@Injectable()
export class RabbitConsumer implements OnModuleInit, OnModuleDestroy, OnApplicationShutdown {
  async onModuleInit() {
    await this.channel.consume('orders', this.handle);
  }
  async onModuleDestroy() {
    await this.channel.cancel(this.consumerTag);   // ngừng nhận message mới
  }
  async onApplicationShutdown(signal?: string) {
    await this.connection.close();
  }
}

// main.ts: bắt buộc nếu muốn hook shutdown chạy khi nhận SIGTERM
app.enableShutdownHooks();
  • Hook được await theo từng module; module sâu nhất (xa root nhất) chạy trước, shutdown chạy ngược lại.
  • Không chạy với provider REQUEST-scoped và module lazy-load.
  • app.close() không tự thoát process; timer còn chạy sẽ giữ process sống.

Discovery service

DiscoveryService (từ @nestjs/core) cho phép quét mọi provider/controller lúc khởi động và lọc theo metadata. Đây là nền tảng để tự viết cơ chế kiểu @OnEvent, @Cron, hay một "plugin registry".

import { DiscoveryModule, DiscoveryService } from '@nestjs/core';

// 1. decorator đánh dấu class
export const RuleEvaluator = DiscoveryService.createDecorator<{ type: string }>();

@RuleEvaluator({ type: 'ip' })
@Injectable()
export class IpRuleEvaluator implements Evaluator { evaluate(ctx: Ctx) { /* ... */ } }

// 2. registry quét lúc khởi động
@Injectable()
export class EvaluatorRegistry implements OnModuleInit {
  private readonly map = new Map();
  constructor(private readonly discovery: DiscoveryService) {}

  onModuleInit() {
    for (const wrapper of this.discovery.getProviders({ metadataKey: RuleEvaluator.KEY })) {
      const meta = this.discovery.getMetadataByDecorator(RuleEvaluator, wrapper);
      if (meta && wrapper.instance) this.map.set(meta.type, wrapper.instance);
    }
  }
  get(type: string) { return this.map.get(type); }
}

@Module({ imports: [DiscoveryModule], providers: [EvaluatorRegistry, IpRuleEvaluator] })
export class RulesModule {}

Testing

@nestjs/testing dựng một module DI thu nhỏ để test. Nest 11 dùng Jest mặc định; Nest 12 dùng Vitest cho project ESM.

Unit test service, mock phụ thuộc

import { Test } from '@nestjs/testing';
import { getModelToken } from '@nestjs/mongoose';

describe('CatsService', () => {
  let service: CatsService;
  const catModel = { findById: jest.fn() };

  beforeEach(async () => {
    const moduleRef = await Test.createTestingModule({
      providers: [
        CatsService,
        { provide: getModelToken(Cat.name), useValue: catModel },
      ],
    }).compile();

    service = moduleRef.get(CatsService);
  });

  it('ném NotFound khi không có cat', async () => {
    catModel.findById.mockReturnValue({ lean: () => Promise.resolve(null) });
    await expect(service.findOne('x')).rejects.toBeInstanceOf(NotFoundException);
  });
});
