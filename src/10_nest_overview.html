NestJS là gì

NestJS là framework Node.js để viết ứng dụng phía server bằng TypeScript. Nest không tự xử lý HTTP mà chạy trên một HTTP adapter: mặc định là Express, có thể đổi sang Fastify (từ v12.3 có thêm Node adapter dùng thẳng node:http). Phần Nest thêm vào là kiến trúc: chia ứng dụng thành module, quản lý phụ thuộc bằng Dependency Injection (DI), và khai báo hành vi bằng decorator.

Ba ý tưởng cốt lõi cần nắm trước khi đọc tiếp:

  • Module gom các class liên quan thành một khối có ranh giới rõ ràng. Mọi ứng dụng có ít nhất một root module (AppModule).
  • Provider + DI: class đánh dấu @Injectable() được Nest tạo instance và "tiêm" vào constructor của class khác. Bạn không tự gọi new.
  • Decorator + metadata: @Controller, @Get, @UseGuards… gắn metadata lên class/method, Nest đọc metadata đó lúc khởi động để dựng route và pipeline xử lý request.

File main.ts

NestFactory.create() đọc root module, dựng toàn bộ cây DI, đăng ký route rồi trả về instance ứng dụng. Mọi cấu hình toàn cục (prefix, CORS, pipe global…) đặt ở đây.

import { NestFactory } from '@nestjs/core';
import { ValidationPipe, VersioningType } from '@nestjs/common';
import { NestExpressApplication } from '@nestjs/platform-express';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule, {
    bufferLogs: true,     // giữ log khởi động cho tới khi gắn logger tùy chỉnh
    rawBody: true,        // cần khi verify chữ ký webhook (Shopify, Stripe…)
  });

  app.setGlobalPrefix('api');                     // mọi route bắt đầu bằng /api
  app.enableVersioning({ type: VersioningType.URI }); // /api/v1/...
  app.enableCors({ origin: ['https://admin.example.com'], credentials: true });
  app.useGlobalPipes(new ValidationPipe({ whitelist: true, transform: true }));
  app.enableShutdownHooks();                      // để onModuleDestroy chạy khi nhận SIGTERM

  await app.listen(process.env.PORT ?? 3000);
}
bootstrap();

Kiến trúc và vòng đời request

Nest có tám loại "viên gạch". Hiểu mỗi loại làm gì và chạy ở đâu trong vòng đời request là phần quan trọng nhất của framework.

Controller@Controller()Nhận request, gọi service, trả response. Không chứa business logic.
Provider@Injectable()Service, repository, factory, helper… mọi thứ được DI quản lý.

Thứ tự xử lý một request

Thứ tự dưới đây lấy từ trang FAQ "Request lifecycle" của docs chính thức.

  1. Request đếnAdapter (Express/Fastify) nhận HTTP request.
  2. MiddlewareMiddleware global (app.use) → middleware gắn theo module. Module @Global() chạy trước, root module, rồi các module khác theo khoảng cách tới root.
  3. GuardsGlobal → controller → route. Guard nào trả false thì dừng với 403.
  4. Interceptors (trước handler)Global → controller → route.
  5. PipesGlobal → controller → route → pipe gắn trên từng tham số (tham số cuối chạy trước).
  6. Controller handlerMethod gắn @Get/@Post… được gọi.
  7. ServiceBusiness logic, gọi DB, gọi API ngoài.
  8. Interceptors (sau handler)Chiều ngược lại: route → controller → global.
  9. Exception filtersChỉ chạy khi có exception chưa bắt. Route → controller → global, và chỉ một filter xử lý (không chạy nối tiếp).
  10. ResponseAdapter gửi kết quả về client.

Tương tự có APP_INTERCEPTOR, APP_PIPE, APP_FILTER (import từ @nestjs/core). Truyền class thay vì instance để Nest tự tạo và inject phụ thuộc.

import { Module } from '@nestjs/common';
import { APP_FILTER, APP_GUARD, APP_INTERCEPTOR } from '@nestjs/core';

@Module({
  providers: [
    { provide: APP_GUARD, useClass: AuthGuard },            // chạy trước
    { provide: APP_GUARD, useClass: RolesGuard },           // chạy sau (theo thứ tự đăng ký)
    { provide: APP_INTERCEPTOR, useClass: ResponseInterceptor },
    { provide: APP_FILTER, useClass: AllExceptionsFilter },
  ],
})
export class AppModule {}

Controllers

Controller nhận request và trả response. Decorator @Controller('cats') đặt prefix đường dẫn; decorator HTTP method trên từng method khai báo route con.

import {
  Body, Controller, Delete, Get, HttpCode, HttpStatus, Param,
  ParseIntPipe, Patch, Post, Query, Header, Redirect,
} from '@nestjs/common';
import { CatsService } from './cats.service';
import { CreateCatDto, UpdateCatDto, ListCatsQuery } from './dto';

@Controller('cats')                         // prefix: /cats
export class CatsController {
  constructor(private readonly catsService: CatsService) {}

  @Post()                                   // POST /cats  → mặc định 201
  create(@Body() dto: CreateCatDto) {
    return this.catsService.create(dto);
  }

  @Get()                                    // GET /cats?page=1&limit=20
  findAll(@Query() query: ListCatsQuery) {
    return this.catsService.findAll(query);
  }

  @Get(':id')                               // GET /cats/42
  findOne(@Param('id', ParseIntPipe) id: number) {
    return this.catsService.findOne(id);
  }

  @Patch(':id')
  update(@Param('id', ParseIntPipe) id: number, @Body() dto: UpdateCatDto) {
    return this.catsService.update(id, dto);
  }

  @Delete(':id')
  @HttpCode(HttpStatus.NO_CONTENT)          // đổi status mặc định 200 → 204
  remove(@Param('id', ParseIntPipe) id: number) {
    return this.catsService.remove(id);
  }

  @Get('docs')
  @Redirect('https://docs.nestjs.com', 302)
  docs() {}

  @Get('export.csv')
  @Header('Content-Type', 'text/csv')
  exportCsv() {
    return 'id,name\n1,Tom';
  }
}

Controller phải được khai báo trong mảng controllers của một module thì Nest mới đăng ký route.

Giá trị trả về và @Res()

Handler có thể trả về giá trị thường, Promise hoặc Observable. Nest tự serialize object/array thành JSON. Status mặc định là 200, riêng POST là 201.

Khi inject @Res(), bạn chuyển sang chế độ "tự quản response": Nest không gửi response giùm nữa, interceptor và @HttpCode không còn tác dụng. Nếu chỉ cần set cookie hay header, dùng passthrough:

@Get()
findAll(@Res({ passthrough: true }) res: Response) {
  res.setHeader('X-Total-Count', '120');
  return this.catsService.findAll();   // Nest vẫn gửi body như bình thường
}

Thứ tự route và wildcard

  • Route được đăng ký theo thứ tự khai báo. Nếu @Get(':id') đứng trước @Get('me'), request /users/me sẽ rơi vào :id. Luôn đặt route tĩnh lên trước route có tham số.
  • Express 5 (Nest 11+) bắt buộc wildcard có tên: dùng 'files/*path' hoặc 'files/{*path}' (dạng có ngoặc nhọn khớp cả /files). Dạng '*' trần đã deprecated.
  • Sub-domain: @Controller({'{'} host: ':account.example.com' {'}'}) rồi đọc bằng @HostParam('account') (không hỗ trợ trên Fastify).
Mẹo

DTO phải là class, không phải interface. Interface bị xóa khi biên dịch nên ValidationPipe và Swagger không đọc được kiểu. Cũng đừng dùng import type cho DTO.

Providers và Dependency Injection

Provider là bất kỳ class nào được đánh dấu @Injectable() và khai báo trong providers của module. Nest tạo instance (mặc định là singleton, mỗi app một instance) và inject vào nơi cần qua constructor.

import { Injectable, NotFoundException } from '@nestjs/common';
import { InjectModel } from '@nestjs/mongoose';
import { Model } from 'mongoose';
import { Cat } from './schemas/cat.schema';

@Injectable()
export class CatsService {
  constructor(@InjectModel(Cat.name) private readonly catModel: Model) {}

  async findOne(id: string) {
    const cat = await this.catModel.findById(id).lean();
    if (!cat) throw new NotFoundException(`Cat ${id} not found`);
    return cat;
  }
}

Nest resolve phụ thuộc thế nào

  1. Lúc khởi động, Nest đọc kiểu tham số constructor (TypeScript phát metadata design:paramtypes nhờ emitDecoratorMetadata).
  2. Kiểu đó chính là token. Nest tìm provider có token tương ứng trong module hiện tại, rồi trong các module được import (chỉ những gì chúng exports).
  3. Nếu chưa có instance thì tạo, đệ quy cho phụ thuộc của nó, rồi cache lại.

Vì token lấy từ kiểu runtime, bạn không thể inject bằng interface hay import type. Khi đó dùng token chuỗi/Symbol với @Inject(), hoặc dùng abstract class làm token (xem Repository pattern).

export const PAYMENT_GATEWAY = Symbol('PAYMENT_GATEWAY');

@Injectable()
export class CheckoutService {
  constructor(
    @Inject(PAYMENT_GATEWAY) private readonly gateway: PaymentGateway, // token Symbol
    @Optional() private readonly metrics?: MetricsService,             // không có cũng không lỗi
  ) {}
}
Lỗi hay gặp

Nest can't resolve dependencies of the CatsService (?): dấu ? chỉ vị trí tham số không resolve được. Thường do (1) quên thêm provider vào module, (2) module chứa provider chưa exports nó, (3) module hiện tại chưa imports module kia, hoặc (4) circular import khiến kiểu là undefined.

Modules

Module là đơn vị tổ chức code. Metadata của @Module() có bốn khóa:

KhóaÝ nghĩa
importsCác module khác mà module này cần dùng provider của chúng.
controllersController thuộc module này.
providersProvider được tạo trong module này, dùng nội bộ.
exportsTập con của providers (hoặc module đã import) mà module khác được phép dùng.
@Module({
  imports: [MongooseModule.forFeature([{ name: Cat.name, schema: CatSchema }])],
  controllers: [CatsController],
  providers: [CatsService, CatsRepository],
  exports: [CatsService],          // module khác import CatsModule sẽ dùng được CatsService
})
export class CatsModule {}

Đóng gói (encapsulation)

Provider mặc định là "private" trong module. Muốn dùng CatsService trong OrdersModule, bạn phải export ở CatsModule và import CatsModule trong OrdersModule. Đừng khai báo lại CatsService trong providers của module khác: làm vậy tạo ra instance thứ hai, mất tính singleton.

Re-export và module dùng chung

@Module({
  imports: [DatabaseModule, RedisModule],
  exports: [DatabaseModule, RedisModule],   // ai import CoreModule sẽ có luôn cả hai
})
export class CoreModule {}

Global module

@Global() khiến các export của module có mặt ở mọi nơi mà không cần import. Hợp với thứ thật sự dùng khắp nơi như config, logger, Redis client. Đừng lạm dụng: global làm mất dấu vết phụ thuộc và khó test.

@Global()
@Module({ providers: [RedisService], exports: [RedisService] })
export class RedisModule {}

Module có thể nhận cấu hình lúc import (dynamic module, như MongooseModule.forRoot(uri)). Phần này được trình bày riêng ở mục Dynamic modules.

Middleware

Middleware chạy trước guard, khi Nest chưa xác định handler nào sẽ xử lý. Vì vậy middleware không biết controller/method đích, không đọc được metadata của decorator. Dùng nó cho việc cấp thấp: gắn request-id, log thô, parse body, CORS tùy biến.

import { Injectable, NestMiddleware } from '@nestjs/common';
import { randomUUID } from 'node:crypto';
import { NextFunction, Request, Response } from 'express';

@Injectable()
export class RequestIdMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction) {
    const id = (req.headers['x-request-id'] as string) ?? randomUUID();
    req.headers['x-request-id'] = id;
    res.setHeader('x-request-id', id);
    next();                       // quên gọi next() thì request treo
  }
}

// middleware dạng hàm: không cần DI thì nên dùng dạng này
export function timing(req: Request, res: Response, next: NextFunction) {
  const start = Date.now();
  res.on('finish', () => console.log(`${req.method} ${req.originalUrl} ${Date.now() - start}ms`));
  next();
}

Middleware không khai báo trong @Module() mà đăng ký bằng method configure() của module (implement NestModule):

@Module({ controllers: [CatsController] })
export class AppModule implements NestModule {
  configure(consumer: MiddlewareConsumer) {
    consumer
      .apply(RequestIdMiddleware, timing)
      .exclude({ path: 'health', method: RequestMethod.GET })
      .forRoutes('{*splat}');          // mọi route (cú pháp Express 5)

    consumer
      .apply(ShopifyHmacMiddleware)
      .forRoutes({ path: 'webhooks/*path', method: RequestMethod.POST }, WebhooksController);
  }
}
  • forRoutes nhận chuỗi path, object {'{'} path, method {'}'} hoặc class controller.
  • Middleware global không cần DI: app.use(timing) trong main.ts.
  • Exception ném ra trong middleware chỉ được xử lý bởi exception filter global.

Exception filters

Nest có sẵn một exception layer toàn cục. Exception là HttpException (hoặc lớp con) được trả về đúng status và body; mọi lỗi khác trở thành 500 {'{'} "statusCode": 500, "message": "Internal server error" {'}'}.

Ném lỗi HTTP

throw new HttpException('Forbidden', HttpStatus.FORBIDDEN);
// → { "statusCode": 403, "message": "Forbidden" }

throw new HttpException({ code: 'QUOTA_EXCEEDED', limit: 1000 }, 429);
// object thay thế toàn bộ body

throw new BadRequestException('Email đã tồn tại', {
  cause: err,                      // chỉ dùng để log, không gửi cho client
  description: 'Duplicate email',  // điền vào trường "error"
});
// → { "statusCode": 400, "message": "Email đã tồn tại", "error": "Duplicate email" }

Các exception dựng sẵn trong @nestjs/common: BadRequestException, UnauthorizedException, ForbiddenException, NotFoundException, MethodNotAllowedException, NotAcceptableException, RequestTimeoutException, ConflictException, GoneException, PreconditionFailedException, PayloadTooLargeException, UnsupportedMediaTypeException, UnprocessableEntityException, ImATeapotException, MisdirectedException, InternalServerErrorException, NotImplementedException, BadGatewayException, ServiceUnavailableException, GatewayTimeoutException, HttpVersionNotSupportedException.

Viết filter riêng

Filter implement ExceptionFilter, method catch(exception, host) nhận exception và ArgumentsHost để lấy request/response. @Catch(Type) giới hạn loại exception; @Catch() rỗng bắt tất cả.

import { ArgumentsHost, Catch, ExceptionFilter, HttpException, HttpStatus, Logger } from '@nestjs/common';
import { HttpAdapterHost } from '@nestjs/core';

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  private readonly logger = new Logger(AllExceptionsFilter.name);

  constructor(private readonly adapterHost: HttpAdapterHost) {}

  catch(exception: unknown, host: ArgumentsHost) {
    const { httpAdapter } = this.adapterHost;       // dùng adapter để chạy được cả Express lẫn Fastify
    const ctx = host.switchToHttp();
    const req = ctx.getRequest();

    const status = exception instanceof HttpException
      ? exception.getStatus()
      : HttpStatus.INTERNAL_SERVER_ERROR;

    const body = exception instanceof HttpException
      ? exception.getResponse()
      : { message: 'Internal server error' };

    if (status >= 500) this.logger.error(exception);

    httpAdapter.reply(ctx.getResponse(), {
      success: false,
      statusCode: status,
      path: httpAdapter.getRequestUrl(req),
      timestamp: new Date().toISOString(),
      error: body,
    }, status);
  }
}

Gắn filter: @UseFilters(HttpExceptionFilter) trên method/controller, hoặc toàn cục bằng {'{'} provide: APP_FILTER, useClass: AllExceptionsFilter {'}'}. Muốn giữ hành vi mặc định và chỉ thêm chút logic, kế thừa BaseExceptionFilter rồi gọi super.catch().

Lưu ý
  • app.useGlobalFilters() không áp dụng cho WebSocket gateway và microservice trong hybrid app.
  • Filter không chạy nối tiếp: filter cấp route đã bắt thì filter global không thấy exception đó.
  • Trên Fastify dùng response.send() thay vì response.json().

Pipes

Pipe chạy ngay trước handler, nhận giá trị tham số và làm một trong hai việc: transform (đổi chuỗi "42" thành số 42) hoặc validate (ném exception nếu dữ liệu sai, khi đó handler không được gọi).

find(@Param('id', new ParseIntPipe({ errorHttpStatusCode: HttpStatus.NOT_ACCEPTABLE })) id: number) {}

Viết pipe riêng

Ví dụ: pipe kiểm tra chuỗi là MongoDB ObjectId hợp lệ, tránh lỗi CastError từ Mongoose.

import { ArgumentMetadata, BadRequestException, Injectable, PipeTransform } from '@nestjs/common';
import { Types } from 'mongoose';

@Injectable()
export class ParseObjectIdPipe implements PipeTransform {
  transform(value: string, metadata: ArgumentMetadata) {
    // metadata = { type: 'param' | 'query' | 'body' | 'custom', metatype, data: 'id' }
    if (!Types.ObjectId.isValid(value)) {
      throw new BadRequestException(`${metadata.data} không phải ObjectId hợp lệ`);
    }
    return new Types.ObjectId(value);
  }
}

// dùng:
@Get(':id')
findOne(@Param('id', ParseObjectIdPipe) id: Types.ObjectId) {}

Validate DTO với ValidationPipe là chủ đề lớn, được trình bày ở mục Validation và Serialization.

Guards

Guard có một trách nhiệm: trả lời "request này có được đi tiếp không". Khác middleware, guard có ExecutionContext nên biết handler và controller đích, đọc được metadata do decorator gắn. Vì vậy xác thực và phân quyền đặt ở guard.

import { Reflector } from '@nestjs/core';

export type Role = 'admin' | 'staff' | 'merchant';
export const Roles = Reflector.createDecorator();   // tạo decorator có kiểu

import { CanActivate, ExecutionContext, Injectable } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { Roles } from './roles.decorator';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    // ưu tiên metadata trên method, nếu không có thì lấy trên class
    const required = this.reflector.getAllAndOverride(Roles, [
      context.getHandler(),
      context.getClass(),
    ]);
    if (!required?.length) return true;

    const { user } = context.switchToHttp().getRequest();
    return required.some((role) => user?.roles?.includes(role));
  }
}

@Controller('settings')
@UseGuards(AuthGuard, RolesGuard)
export class SettingsController {
  @Patch()
  @Roles(['admin'])
  update(@Body() dto: UpdateSettingsDto) {}
}
  • Guard trả false → Nest ném ForbiddenException (403, "Forbidden resource"). Muốn 401 hoặc message khác thì tự throw.
  • canActivate có thể trả boolean, Promise<boolean> hoặc Observable<boolean>.
  • Nhiều APP_GUARD chạy theo thứ tự đăng ký. Ví dụ đầy đủ về JWT ở mục Bảo mật.

Interceptors

Interceptor bọc quanh lời gọi handler theo kiểu AOP. Method intercept(context, next) chạy logic trước, gọi next.handle() để thực thi handler (trả về Observable), rồi dùng toán tử RxJS để xử lý kết quả. Không gọi next.handle() thì handler không chạy.

Đo thời gian xử lý

@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  private readonly logger = new Logger('HTTP');

  intercept(context: ExecutionContext, next: CallHandler): Observable {
    const req = context.switchToHttp().getRequest();
    const start = Date.now();
    return next.handle().pipe(
      finalize(() => this.logger.log(`${req.method} ${req.url} ${Date.now() - start}ms`)),
    );
  }
}

Bọc response theo một format chung

export interface Envelope { success: true; data: T }

@Injectable()
export class ResponseInterceptor implements NestInterceptor> {
  intercept(_: ExecutionContext, next: CallHandler): Observable> {
    return next.handle().pipe(map((data) => ({ success: true, data })));
  }
}

Đổi exception và đặt timeout

@Injectable()
export class TimeoutInterceptor implements NestInterceptor {
  intercept(_: ExecutionContext, next: CallHandler) {
    return next.handle().pipe(
      timeout(5000),
      catchError((err) =>
        err instanceof TimeoutError
          ? throwError(() => new RequestTimeoutException())
          : throwError(() => err),
      ),
    );
  }
}

Bỏ qua handler (cache)

@Injectable()
export class SimpleCacheInterceptor implements NestInterceptor {
  constructor(private readonly cache: CacheService) {}

  async intercept(ctx: ExecutionContext, next: CallHandler) {
    const key = ctx.switchToHttp().getRequest().url;
    const hit = await this.cache.get(key);
    if (hit) return of(hit);                       // trả luôn, handler không chạy
    return next.handle().pipe(tap((data) => this.cache.set(key, data, 60_000)));
  }
}
Ghi nhớ

tap không chạy khi handler lỗi. Cần dọn dẹp trong mọi trường hợp thì dùng finalize. Unsubscribe do timeout không hủy được công việc handler đã bắt đầu.

Custom decorators

Decorator tham số

createParamDecorator tạo decorator lấy dữ liệu từ request, giúp controller không phải đụng tới @Req().

import { createParamDecorator, ExecutionContext } from '@nestjs/common';

export const CurrentShop = createParamDecorator(
  (field: keyof ShopContext | undefined, ctx: ExecutionContext) => {
    const shop: ShopContext = ctx.switchToHttp().getRequest().shop; // do guard gắn vào
    return field ? shop?.[field] : shop;
  },
);

// dùng:
@Get('me')
me(@CurrentShop() shop: ShopContext, @CurrentShop('domain') domain: string) {}

Pipe vẫn chạy trên tham số custom. Muốn ValidationPipe validate luôn giá trị từ decorator custom, bật validateCustomDecorators: true.

Gộp nhiều decorator

applyDecorators gộp nhiều decorator thành một, rất hợp để chuẩn hóa cách khai báo route bảo mật.

import { applyDecorators, UseGuards } from '@nestjs/common';
import { ApiBearerAuth, ApiUnauthorizedResponse } from '@nestjs/swagger';

export function Auth(...roles: Role[]) {
  return applyDecorators(
    Roles(roles),
    UseGuards(AuthGuard, RolesGuard),
    ApiBearerAuth(),
    ApiUnauthorizedResponse({ description: 'Unauthorized' }),
  );
}

@Delete(':id')
@Auth('admin')
remove() {}
