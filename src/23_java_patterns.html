Static factory và Factory Method

Static factory method thay constructor: có tên gợi nghĩa, có thể trả object cache sẵn, trả lớp con, hoặc trả kiểu interface để giấu cài đặt.

public sealed interface Notifier permits EmailNotifier, SlackNotifier {
    void send(String to, String msg);

    static Notifier of(Channel channel, Config cfg) {       // factory method
        return switch (channel) {
            case EMAIL -> new EmailNotifier(cfg.smtpHost());
            case SLACK -> new SlackNotifier(cfg.slackWebhook());
        };
    }
}

Builder

Dùng khi object có nhiều tham số tùy chọn: tránh constructor dài với cả chục tham số cùng kiểu dễ truyền nhầm thứ tự.

public record HttpRetryPolicy(int maxAttempts, Duration baseDelay, Duration maxDelay,
                              Set retryOn, boolean jitter) {

    public static Builder builder() { return new Builder(); }

    public static final class Builder {
        private int maxAttempts = 3;                          // giá trị mặc định
        private Duration baseDelay = Duration.ofMillis(200);
        private Duration maxDelay = Duration.ofSeconds(10);
        private Set retryOn = Set.of(429, 502, 503, 504);
        private boolean jitter = true;

        public Builder maxAttempts(int v) { this.maxAttempts = v; return this; }
        public Builder baseDelay(Duration v) { this.baseDelay = v; return this; }
        public Builder maxDelay(Duration v) { this.maxDelay = v; return this; }
        public Builder retryOn(Integer... codes) { this.retryOn = Set.of(codes); return this; }
        public Builder jitter(boolean v) { this.jitter = v; return this; }

        public HttpRetryPolicy build() {
            if (maxAttempts < 1) throw new IllegalStateException("maxAttempts >= 1");
            return new HttpRetryPolicy(maxAttempts, baseDelay, maxDelay, retryOn, jitter);
        }
    }
}

var policy = HttpRetryPolicy.builder().maxAttempts(5).retryOn(503).build();

Record có ít tham số thì không cần builder; thêm vài static factory là đủ. Thư viện Lombok lib sinh builder bằng @Builder nếu dự án đã dùng nó.

Adapter

Bọc một API bên ngoài để nó khớp với interface mà code của bạn mong đợi. Đây cũng là "adapter" trong kiến trúc Ports & Adapters.

// port của ứng dụng
public interface GeoLookup {
    GeoInfo lookup(String ip);
}

// SDK bên ngoài có API khác
// MaxMindReader.city(InetAddress) -> CityResponse

public final class MaxMindGeoAdapter implements GeoLookup {
    private final MaxMindReader reader;
    public MaxMindGeoAdapter(MaxMindReader reader) { this.reader = reader; }

    @Override public GeoInfo lookup(String ip) {
        try {
            CityResponse r = reader.city(InetAddress.getByName(ip));
            return new GeoInfo(r.country().isoCode(), r.city().name());
        } catch (IOException e) {
            return GeoInfo.UNKNOWN;
        }
    }
}

Decorator

Thêm hành vi (cache, retry, đo thời gian, log) bằng cách bọc object có cùng interface. Có thể xếp chồng nhiều lớp. java.io là ví dụ kinh điển: new BufferedReader(new InputStreamReader(new FileInputStream(f))).

public final class CachingGeoLookup implements GeoLookup {
    private final GeoLookup inner;
    private final Map cache = Collections.synchronizedMap(
        new LinkedHashMap<>(1000, 0.75f, true) {                    // LRU
            @Override protected boolean removeEldestEntry(Map.Entry e) { return size() > 10_000; }
        });

    public CachingGeoLookup(GeoLookup inner) { this.inner = inner; }

    @Override public GeoInfo lookup(String ip) {
        return cache.computeIfAbsent(ip, inner::lookup);
    }
}

public final class TimedGeoLookup implements GeoLookup {
    private final GeoLookup inner;
    private final Timer timer;
    public TimedGeoLookup(GeoLookup inner, Timer timer) { this.inner = inner; this.timer = timer; }
    @Override public GeoInfo lookup(String ip) {
        long t = System.nanoTime();
        try { return inner.lookup(ip); } finally { timer.record(System.nanoTime() - t); }
    }
}

GeoLookup geo = new TimedGeoLookup(new CachingGeoLookup(new MaxMindGeoAdapter(reader)), timer);

Proxy và dynamic proxy

Proxy đứng thay object thật để kiểm soát truy cập: khởi tạo lười, kiểm tra quyền, gọi từ xa, transaction. Java tạo được proxy lúc runtime cho mọi interface; Spring dùng chính cơ chế này cho @Transactional và AOP.

@SuppressWarnings("unchecked")
static  T logged(T target, Class iface) {
    InvocationHandler handler = (proxy, method, args) -> {
        long start = System.nanoTime();
        try {
            return method.invoke(target, args);
        } catch (InvocationTargetException e) {
            throw e.getCause();                                     // ném lỗi gốc, không phải lỗi bọc
        } finally {
            System.out.printf("%s.%s %d µs%n", iface.getSimpleName(), method.getName(),
                              (System.nanoTime() - start) / 1_000);
        }
    };
    return (T) Proxy.newProxyInstance(iface.getClassLoader(), new Class[] { iface }, handler);
}

GeoLookup geo = logged(new MaxMindGeoAdapter(reader), GeoLookup.class);
Self-invocation

Proxy chỉ chặn lời gọi đi qua proxy. Method trong cùng class gọi nhau bằng this.foo() thì bỏ qua proxy, nên @Transactional hay @Cacheable của Spring không có tác dụng trong trường hợp đó.

Strategy

Trong Java hiện đại, strategy thường chỉ là một functional interface: truyền lambda thay vì viết class riêng. Khi strategy có tên cố định, enum với lambda là cách gọn.

// strategy = functional interface
@FunctionalInterface
interface RiskRule { int score(Order order); }

List rules = List.of(
    o -> o.ipCountry().equals(o.billingCountry()) ? 0 : 30,
    o -> o.total().compareTo(new BigDecimal("1000")) > 0 ? 20 : 0,
    o -> o.isProxy() ? 50 : 0
);
int total = rules.stream().mapToInt(r -> r.score(order)).sum();

// strategy có tên: enum
enum Rounding {
    UP(v -> v.setScale(0, RoundingMode.UP)),
    BANKER(v -> v.setScale(0, RoundingMode.HALF_EVEN));

    private final UnaryOperator fn;
    Rounding(UnaryOperator fn) { this.fn = fn; }
    BigDecimal apply(BigDecimal v) { return fn.apply(v); }
}

Dùng class riêng khi strategy có trạng thái, cần nhiều method, hoặc cần phụ thuộc được inject (DB, HTTP client). Với Spring, inject Map<String, RiskRule> để có ngay registry theo tên bean.

Observer

public final class EventBus {
    private final List> listeners = new CopyOnWriteArrayList<>();  // an toàn khi đăng ký lúc đang phát

    public Runnable subscribe(Consumer l) {
        listeners.add(l);
        return () -> listeners.remove(l);                           // trả hàm hủy đăng ký
    }

    public void publish(E event) {
        for (var l : listeners) {
            try { l.accept(event); }
            catch (RuntimeException ex) { log.warn("listener lỗi", ex); }   // một listener lỗi không chặn cái khác
        }
    }
}

Template Method

public abstract class ImportJob {
    // khung cố định: final để lớp con không đổi thứ tự
    public final ImportResult run(Path file) throws IOException {
        try (var lines = Files.lines(file)) {
            List rows = lines.skip(1).map(this::parse).filter(this::isValid).toList();
            save(rows);
            return new ImportResult(rows.size());
        }
    }

    protected abstract R parse(String line);           // bước bắt buộc
    protected boolean isValid(R row) { return true; }   // hook có mặc định
    protected abstract void save(List rows);
}

public final class IpBlocklistImport extends ImportJob {
    @Override protected String parse(String line) { return line.split(",")[0].strip(); }
    @Override protected boolean isValid(String ip) { return InetAddresses.isValid(ip); }
    @Override protected void save(List ips) { repo.blockAll(ips); }
}

Nếu chỉ có một hai bước thay đổi, truyền lambda vào constructor (strategy) thường gọn hơn kế thừa.

State

Mô hình trạng thái bằng sealed interface + record: mỗi trạng thái chỉ mang dữ liệu của nó, chuyển trạng thái được compiler kiểm tra đủ trường hợp.

sealed interface Subscription {
    record Trial(Instant endsAt) implements Subscription {}
    record Active(String planId, Instant renewsAt) implements Subscription {}
    record PastDue(String planId, int failedAttempts) implements Subscription {}
    record Cancelled(Instant at) implements Subscription {}
}

static Subscription onPaymentFailed(Subscription s) {
    return switch (s) {
        case Subscription.Active a -> new Subscription.PastDue(a.planId(), 1);
        case Subscription.PastDue p when p.failedAttempts() >= 3 -> new Subscription.Cancelled(Instant.now());
        case Subscription.PastDue p -> new Subscription.PastDue(p.planId(), p.failedAttempts() + 1);
        case Subscription.Trial t -> t;
        case Subscription.Cancelled c -> c;
    };
}

Chain of Responsibility

Mỗi handler quyết định xử lý hay chuyển cho handler tiếp theo. Đây chính là mô hình của Servlet Filter và middleware trong NestJS/Express.

@FunctionalInterface
interface Check {
    Optional apply(Visitor v);                 // empty = không kết luận, chuyển tiếp
}

final class CheckChain {
    private final List checks;
    CheckChain(List checks) { this.checks = List.copyOf(checks); }

    Verdict evaluate(Visitor v) {
        for (Check c : checks) {
            Optional r = c.apply(v);
            if (r.isPresent()) return r.get();          // handler đầu tiên có kết luận thắng
        }
        return Verdict.ALLOW;
    }
}

var chain = new CheckChain(List.of(
    v -> whitelist.contains(v.ip()) ? Optional.of(Verdict.ALLOW) : Optional.empty(),
    v -> blacklist.contains(v.ip()) ? Optional.of(Verdict.BLOCK) : Optional.empty(),
    v -> v.isBot() ? Optional.of(Verdict.CHALLENGE) : Optional.empty()
));

Visitor và sealed + switch

Visitor cổ điển cần method accept(Visitor) ở mọi class và một interface visitor có method cho từng loại. Với Java 21, sealed interface + pattern matching switch đạt cùng mục đích (thêm thao tác mới mà không sửa các class) với ít code hơn, và compiler báo lỗi khi thiếu trường hợp.

sealed interface Expr permits Num, Add, Mul, Neg {}
record Num(double v) implements Expr {}
record Add(Expr l, Expr r) implements Expr {}
record Mul(Expr l, Expr r) implements Expr {}
record Neg(Expr e) implements Expr {}

// "visitor" 1: tính giá trị
static double eval(Expr e) {
    return switch (e) {
        case Num(var v) -> v;
        case Add(var l, var r) -> eval(l) + eval(r);
        case Mul(var l, var r) -> eval(l) * eval(r);
        case Neg(var x) -> -eval(x);
    };
}

// "visitor" 2: in ra chuỗi, không cần sửa các record
static String show(Expr e) {
    return switch (e) {
        case Num(var v) -> String.valueOf(v);
        case Add(var l, var r) -> "(" + show(l) + " + " + show(r) + ")";
        case Mul(var l, var r) -> show(l) + " * " + show(r);
        case Neg(var x) -> "-" + show(x);
    };
}

Đánh đổi: thêm thao tác mới rất dễ, nhưng thêm loại mới phải sửa mọi switch (compiler sẽ chỉ ra chỗ cần sửa). Khi tập loại mở cho bên ngoài mở rộng, dùng đa hình bằng method trong interface.

Retry, Circuit Breaker, Bulkhead

Gọi dịch vụ ngoài thì phải tính tới lỗi tạm thời. Ba pattern bổ trợ nhau:

Retry

Thử lại lỗi tạm thời với backoff mũ + jitter. Chỉ retry thao tác idempotent.

Circuit Breaker

Lỗi vượt ngưỡng thì "ngắt mạch" (open), trả lỗi ngay; sau một lúc thử lại (half-open) rồi đóng (closed).

Bulkhead

Giới hạn số lời gọi đồng thời tới mỗi dịch vụ để một dịch vụ chậm không nuốt hết tài nguyên.

static  T retry(Callable call, HttpRetryPolicy p) throws Exception {
    for (int attempt = 1; ; attempt++) {
        try {
            return call.call();
        } catch (IOException e) {
            if (attempt >= p.maxAttempts()) throw e;
            long cap = Math.min(p.maxDelay().toMillis(), p.baseDelay().toMillis() << (attempt - 1));
            long sleep = p.jitter() ? ThreadLocalRandom.current().nextLong(cap + 1) : cap;
            Thread.sleep(Duration.ofMillis(sleep));     // rẻ trên virtual thread
        }
    }
}

Production nên dùng Resilience4j lib: có sẵn Retry, CircuitBreaker, Bulkhead, RateLimiter, TimeLimiter, ghép được với nhau và tích hợp Spring Boot bằng annotation.

Producer–Consumer

Tách nơi sinh việc và nơi xử lý bằng một hàng đợi có giới hạn. Hàng đợi đầy thì producer bị chặn lại (back-pressure), tránh tràn bộ nhớ.

BlockingQueue queue = new ArrayBlockingQueue<>(10_000);

// producer: request handler
void onVisit(Visit v) {
    if (!queue.offer(v)) metrics.inc("visits.dropped");   // không chặn request: bỏ khi đầy
}

// consumer: gom theo lô rồi ghi DB
Thread.ofVirtual().start(() -> {
    List batch = new ArrayList<>(500);
    while (!Thread.currentThread().isInterrupted()) {
        try {
            batch.add(queue.take());                         // chờ có phần tử
            queue.drainTo(batch, 499);                       // lấy thêm những gì đang có
            repo.insertMany(batch);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();              // giữ cờ interrupt rồi thoát
        } finally {
            batch.clear();
        }
    }
});

Nguyên tắc viết Java tốt

Tổng hợp từ "Effective Java" (Joshua Bloch) và kinh nghiệm cộng đồng:

  • Cân nhắc static factory thay constructor; dùng builder khi có nhiều tham số tùy chọn; singleton thì dùng enum.
  • Giảm tối đa khả năng sửa đổi: field final, class final hoặc record, sao chép phòng thủ collection.
  • Ưu tiên composition hơn kế thừa; thiết kế cho kế thừa hoặc cấm nó (final, sealed).
  • Override equals thì override cả hashCode.
  • Khai báo biến theo interface: List<X> xs = new ArrayList<>().
  • Trả collection rỗng, đừng trả null. Optional chỉ dùng cho kiểu trả về.
  • Kiểm tra tham số đầu method: Objects.requireNonNull, Objects.checkIndex.
  • Dùng exception đúng loại; không nuốt lỗi; giữ nguyên cause khi bọc lại.
  • Ưu tiên tiện ích của java.util.concurrent hơn wait/notify; ưu tiên dữ liệu bất biến khi chia sẻ giữa các thread.
  • Tiền tệ dùng BigDecimal tạo từ chuỗi (new BigDecimal("0.10")), không dùng double.

LỗiNguyên nhân và cách sửa
So sánh chuỗi bằng ==== so tham chiếu. Dùng a.equals(b) hoặc Objects.equals(a, b).
Integer 127 == 127 đúng, 128 == 128 saiCache của Integer.valueOf chỉ từ -128 tới 127. So sánh wrapper bằng equals.
NullPointerException khi unboxingint x = map.get(k) với key không có. Dùng getOrDefault.
ConcurrentModificationExceptionSửa list trong for-each. Dùng removeIf hoặc Iterator.remove().
new BigDecimal(0.1) ra số dàiTạo từ double mang theo sai số nhị phân. Dùng new BigDecimal("0.1") hoặc BigDecimal.valueOf(0.1).
Rò rỉ file/connectionQuên đóng tài nguyên. Luôn dùng try-with-resources.
ThreadLocal giữ dữ liệu cũThread trong pool được tái sử dụng. Gọi remove() trong finally, hoặc dùng ScopedValue.
Nuốt InterruptedExceptionBắt rồi bỏ qua làm thread không dừng được. Gọi Thread.currentThread().interrupt() hoặc ném tiếp.
JVM bị kill trong containerHeap đặt lớn hơn giới hạn container. Dùng -XX:MaxRAMPercentage.
DeadlockHai thread lấy khóa theo thứ tự ngược nhau. Lấy khóa theo thứ tự cố định; jcmd <pid> Thread.print sẽ chỉ ra deadlock.
